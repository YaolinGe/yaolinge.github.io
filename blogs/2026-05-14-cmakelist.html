CMakeLists.txt — Complete Practical Guide

1. What is CMakeLists.txt?

A CMakeLists.txt file is the main configuration file used by the build system generator :contentReference[oaicite:0]{index=0}.

It describes how a software project should be built in a platform-independent way.

Instead of writing platform-specific build scripts, you describe the project once, and CMake generates the appropriate build system.

2. Core Idea (Important Mental Model)

CMake is not a compiler and not a build tool.

It is a build system generator:

CMakeLists.txt → CMake → Build System (Make/Ninja/VS) → Compiler → Binary

So:

  • You write CMakeLists.txt
  • CMake generates build files
  • Another tool actually compiles your code

3. Why use CMakeLists.txt?

Without CMake: - You write separate build systems for each platform: - Makefiles (Linux) - Visual Studio projects (Windows) - Xcode projects (macOS)

With CMake: - One configuration works everywhere - Easier dependency management - Scales well for large projects - Widely used in industry (LLVM, Qt, Blender ecosystems, etc.)

4. When should you use it?

Use CMake when: - Project has multiple source files - You need external libraries - You want cross-platform builds - You expect project growth or collaboration

Avoid when: - Single-file programs - Very small experiments or scripts

5. Where does CMakeLists.txt go?

Typical structure:

MyProject/ ├── CMakeLists.txt # root build config ├── src/ │ ├── CMakeLists.txt # optional module-level config │ ├── main.cpp │ └── utils.cpp └── include/

CMake supports hierarchical builds, meaning each folder can define its own build rules.

6. Minimal Working Example

cmake_minimum_required(VERSION 3.10)

project(MyApp)

add_executable(MyApp main.cpp)

Explanation: - cmake_minimum_required → required CMake version - project → project name - add_executable → build executable from source

7. Slightly More Realistic Example

cmake_minimum_required(VERSION 3.15)

project(HelloApp)

set(CMAKE_CXX_STANDARD 17)

include_directories(include)

add_executable(HelloApp src/main.cpp src/utils.cpp )

8. Key CMake Concepts

8.1 Targets (core concept)

Everything in CMake revolves around targets.

A target can be: - Executable - Library

add_executable(app main.cpp) add_library(mylib lib.cpp)

8.2 Linking libraries

target_link_libraries(app PRIVATE mylib)

Meaning: - app depends on mylib

8.3 Variables

set(MY_VAR "hello")

Used for configuration values.

8.4 Subdirectories

add_subdirectory(src)

Allows modular project structure.

8.5 Finding external dependencies

find_package(OpenSSL REQUIRED)

Used to locate installed libraries on the system.

9. Example: Multi-folder Project

Project structure

MyProject/ ├── CMakeLists.txt ├── app/ │ ├── CMakeLists.txt │ └── main.cpp ├── lib/ │ ├── CMakeLists.txt │ ├── math.cpp │ └── math.h

Root CMakeLists.txt

cmake_minimum_required(VERSION 3.15)

project(MyProject)

add_subdirectory(lib) add_subdirectory(app)

lib/CMakeLists.txt

add_library(mathlib math.cpp)

target_include_directories(mathlib PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})

app/CMakeLists.txt

add_executable(app main.cpp)

target_link_libraries(app PRIVATE mathlib)

10. Build Workflow

Step 1: Generate build files

cmake -S . -B build

Step 2: Build project

cmake --build build

11. Comparison: CMake vs Makefile

Makefile (:contentReference[oaicite:1]{index=1})

A Makefile is a direct build script used by make.

Example:

app: main.o utils.o g++ main.o utils.o -o app

Characteristics: - Manual dependency tracking - Platform-specific in practice - Direct execution model

12. CMakeLists.txt vs Makefile

Feature Makefile CMake
Type Build script Build generator
Portability Low High
Execution Direct Indirect
Scaling Hard Good
Dependency handling Manual Built-in
Ecosystem Older Modern standard

13. Related Build Tools

  • Make → executes Makefiles
  • Ninja → fast build backend often used by CMake
  • MSBuild → Windows build system
  • Autotools → older GNU build system
  • Meson → modern alternative to CMake

14. Full Build Pipeline

CMakeLists.txt → CMake → Makefile / Ninja / Visual Studio Project → Compiler (g++, clang, MSVC) → Executable

15. Key Takeaway

CMake is best understood as:

A translator between human-readable project descriptions and platform-specific build systems.

16. When NOT to use CMake

Avoid CMake when: - Project is a single file - No external dependencies - Quick scripting experiments

17. Summary

  • CMakeLists.txt = build description file
  • CMake = generator tool
  • Make/Ninja/VS = actual build systems
  • Compiler = final execution layer
